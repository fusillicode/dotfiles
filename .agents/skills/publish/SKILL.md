# Publish

Publish the requested change and required formatter output. Preserve unrelated non-format work. Change request creation always uses draft state and self-assignment; updates preserve draft state and assignees.

1. Resolve repository, worktree/index and dirty hunks, local `HEAD`, source branch, remote/source ref and OID, host, requested/default target, and protected status. Stop before verification, staging, or commit when source state is ambiguous, detached, protected, equals target, or remote is not an ancestor of `HEAD`; report local-only and remote-only commits. Never create or switch branches without explicit name and authority.
2. Resolve exactly one open change request for the exact project/source branch, if any, including repository-scoped identifier, title, description, source SHA, and target; stop on ambiguity. If no open change request exists, resolve the exact authenticated hosting-service username using the host's authenticated current-user operation before verification, staging, commit, or push; stop if the lookup fails. Do not resolve the username when updating an existing change request. Finalize target from user, existing change request, then default. Stop for an unapproved retarget; when authorized, record its original and intended targets.
3. Inspect repository guidance, target diff, untracked files, and commits while preserving unrelated non-format dirty work. Explicit `$publish` authorizes one scoped commit for the requested change and required formatter output if needed, normal push, current-branch change request create/update, creation-time self-assignment, and a requirement-grounded title/description. An explicit amend authorization also authorizes one exact-lease rewrite of the recorded published tip; ask before every other mutation.
4. Run every applicable focused check for changed code and directly affected dependents before formatting. A failed, skipped, timed-out, unavailable, or non-equivalent check blocks publication. If no focused check exists, let CI own broader validation. Format afterward per AGENTS.md; formatter-only changes need no rerun. Repository-wide checks remain CI-owned.
   Delegate long-running or multi-command verification to `check_runner` with exact commands and a writable log directory. Keep check selection and gate acceptance in the parent. Reuse valid results while relevant inputs and environment remain unchanged.
5. Read `../_shared/commit-msg.md`, stage the requested changes and formatter output while preserving unrelated non-format hunks, and validate the message. For an authorized amend, distinguish the published tip from an absent or ancestor unpublished tip; use `--no-edit` only for a valid existing message, otherwise a validated replacement. Without amend authority, create a new commit when needed. After an unpublished amend with a remote ref, require its OID to remain an ancestor of new `HEAD`. Never create an empty commit.
6. Immediately before push, re-read the exact source ref and stop if existence changed or an amended existing ref differs from recorded OID. Build `<head-refspec>` as one shell-escaped `HEAD:refs/heads/<source-branch>` argument. Normal updates, absent refs, and unpublished-tip amends use `git push --set-upstream origin <head-refspec>`. Only a published-tip amend uses `git push <lease> origin <head-refspec>`, with `--force-with-lease=refs/heads/<source-branch>:<recorded-oid>`. Pass refspec and lease separately; never use plain or implicit force or another destination.
7. After push, resolve the exact open change request once. Require its target and source SHA to match, except an authorized retarget must retain its recorded original target until writing. Update an exact newly appeared change request rather than creating a duplicate; stop if a known change request disappears or changes identity, target, or source. Snapshot repository-scoped identifier, title, description, assignees, and draft state.
8. Read `../_shared/change-desc.md`; the description must satisfy it. Validate the title separately. Write from the post-push snapshot. For creation, use the exact authenticated username resolved in step 2, then supply exact repository, source, target, title, description, draft state, and that username as assignee. For update, omit draft and assignee mutation fields or flags; preserve the snapshot's draft state and assignee list exactly. Never pass source on update, and pass the target branch only for the separately authorized retarget. The workflow authorizes this write.
9. Re-read and verify the change request. On creation, require draft state and the authenticated user as assignee. On update, require draft state and assignees to equal the pre-write snapshot. Report change request URL, actual draft/ready state, assignee, target, commit, and pushed ref.
